    ADR-0001: Alignment Quality Gates and Ownership Split

    • Status: Accepted
    • Date: 2026-10-13
    • Decision Makers: Ribocode maintainers

    Multi-chain fitting handoff (2026-11-24)

    PR #170 was merged into shared main. Local main was fast-forwarded to merge commit a5aa56bb2d918d73d799d9da045b7fe3a8dfc063; the current work branch investigate/multi-chain-fitting starts there. The fork's main has not been updated. Ribocode pins Mol* commit 901cef218be8f231ebb749160e83d586be77ab34, which is reachable from the shared Mol* investigate/ribocode-on-5.13.1 branch. Keep that branch available while Ribocode depends on it.

    The developer-only multi-chain fitting experiment is implemented behind ?experimentalMultiChainAlignment=1. Production alignment remains unchanged. The agreed design:

    • Pair selected chains by slot, including fixed and dynamic slots. Block the experimental fit with an explicit explanation if either side of an occupied slot is missing or ambiguous; never silently omit a selected pair.
    • Prefer at least 10 unambiguous shared residue-key anchors per pair. If these are insufficient, use the explicitly reported protein sequence fallback subject to the safeguards in the testing reference. Never substitute ordered pairing. Neither shared keys nor sequence alignment prove biological correspondence.
    • Fit one shared transform with equal weight per matched anchor pair. Do not automatically exclude displaced chains. Show a persistent in-page report with each pair's matched and observed anchor counts, coverage, shared-fit RMSD and individual-fit RMSD so users can assess trade-offs.

    The default path in src/App.tsx still collects only the first two chain slots; its anchor path uses only the first pair and its fallback can pair residues by order. The experiment instead matches author residue number, insertion code and component, excludes duplicate keys and counts unmatched observed anchors in coverage. Unknown insertion codes are treated as blank, with an explicit report warning and count, to allow the 7WTT/7WTZ fixtures to be investigated. This is an assumption, not evidence that the codes are actually blank. The 6XU6/6xu8 CU pair instead needs the sequence fallback: its 55 identical observed residues have no shared author numbers. See the alignment testing reference for use and limitations.

    Focused tests cover the e/E and T/F/K fixtures, incomplete slots, duplicate keys, multiple anchor types and degenerate fits. Browser checks cover the persistent report and failure behavior. The real 6XU6/6xu8 CU/CP combination also exercises sequence and residue-key correspondence in one shared fit. CP's atom-site insertion codes are unknown even though its sequence-scheme records have no insertion code; the warning remains appropriate.

    Deliberately mismatched CP/CO passes the current ten-key rule with only 14 matches and an individual RMSD of approximately 20.135 Angstrom. Conversely, CP/CU is rejected by the sequence trace safeguard. Acceptance does not validate correspondence. The experimental report warns per row when residue-key coverage is below 50% on either side but still applies the fit; exactly 50% does not warn. This also warns for the previously studied low-coverage e/e pair without excluding it. Stricter quality criteria remain an open policy decision; the experiment must not be presented as production-ready. Broader structure validation, experimental initial-alignment session round trips and a production correspondence/weighting policy remain outstanding before release qualification; this handoff does not establish 0.25.0 readiness.

    Current investigation status (2026-11-23)

    • Weak-case follow-up: both 7WTT and 7WTZ contain distinct author chains E and e. Case-sensitive anchor, atom and residue lookup now distinguishes them, prioritizes exact author IDs over label aliases, and rejects ambiguous case-insensitive fallback matches. A forced-WebGL browser run found 262 E anchors in each structure and 20 and 55 e anchors in the reference and moving structures respectively. The e-to-e fit used 20 pairs, with RMSD 0.354 Angstrom and improvement ratio 8.44; it covers only 20 of the moving chain's 55 anchors. The old 262-pair, 72.233 Angstrom result used the wrong chain and is not comparable. The previous sequence-identical 20-pair analysis remains a separate offline metric.
    • The same browser run retained the CU-to-CU result: 95 pairs, RMSD 5.999 Angstrom and improvement ratio 18.00. These results do not establish a general correspondence policy or qualify the release. Chain and residue loci now use the same chain resolution for selection, highlighting and zoom; residue loci also apply a supplied insertion code. Case-normalized custom chain colors remain a separate limitation.
    • Multi-chain alignment has a separate limitation: when the first selected pair has enough anchors, the fit uses that pair's anchors only, even though metrics list both pairs. Element-data fallback combines selected chains. A separate correspondence policy and regression are needed before changing this behavior. In a forced-WebGL run selecting e/E in both 7WTT and 7WTZ, the metric listed both pairs but remained at 20 pairs, exactly the single e-pair count. Combined two-chain highlighting passed a separate forced-WebGL browser check.
    • An offline weighting diagnostic now compares a shared per-atom fit with equal total weight per pair, reporting observed-anchor coverage and per-pair shared/individual RMSDs. For e/E, both pairs fit well together, while e covers only 20/55 moving anchors. The results and correspondence limitations are in the alignment testing reference; they do not justify a production weighting or automatic exclusion policy.
    • A screened real conflict in 7WTT/7WTZ (T, F and K) shows that the weighting can change which selected chains have the largest shared-fit residuals. T/F fit well without K, while K is displaced under their transform. This is a diagnostic observation, not a confirmed biological explanation or a reason to automatically exclude a chain; see the testing reference for per-pair coverage and measured values.
    • Improved initial alignment remains a developer-only experiment; production defaults have not changed. Manual 6XU6/6XU8 comparison was positive.
    • Geometry source/runtime mismatch is resolved and pinned to Mol* commit 2d4fd2c68fe4cdf600ebb38a84e9030bed4f8725; formerly failing geometry tests now pass.
    • An instrumented full-CU residue regression passed all assertions in 176 seconds. The previous 120-second budget could expire during loading or controls before fitting. Its readiness wait now requires the Aligned visibility control's accessible label to indicate Hide, rather than matching the disabled Show Aligned placeholder. Full-ribosome residue tests and the related clipping/repeat-alignment workflows use 240 seconds; the smaller AlphaFold test budget and all numerical assertions are unchanged. Aligned readiness allows up to 120 seconds for cold loading.
    • Full PR-suite qualification, a passing full Mol* library build, experimental session round trips and broader structure validation remain required before release.
    • The persistent camera-parity failure was reproduced with forced software WebGL: position, target and up matched exactly, but radius was 173.195677 in A versus 172.354395 in B (difference 0.841282). Default browser runs could pass, so both modes matter when qualifying this regression.
    • Root cause: Mol* reports clipping radius as a rounded integer percentage of the scene radius. App camera-event readback updated the clipping controls, whose fog/clipping effect wrote that percentage back to Mol*, quantizing the exact radius just copied during realignment. The effect now omits radius when the requested percentage already matches Mol*; intentional slider changes still apply.
    • With that fix, all three residue regressions pass under forced software WebGL, including the unchanged camera threshold of 0.0001. Camera parity also passed a second focused run. Related reset-zoom, wheel/selection-mode clipping, live clipping and repeat-alignment checks pass across focused runs. Live clipping's interactive close/reopen check needs a 20-second polling budget on this environment.
    • Camera helper/context/sync unit coverage passes (31 tests). TypeScript reports only the two previously known container TS2454 errors in MolstarContainer.test.tsx; the production Vite/PWA bundle builds successfully. Full PR-suite and full Mol* build qualification remain outstanding.

    The dated investigation sections preserve historical observations. Statements about deliberately failing geometry tests or unresolved provenance describe earlier checkpoints, not the current state.

    The camera check now requires both snapshots and polls the same threshold instead of silently skipping missing snapshots or using a fixed final delay. On failure it includes normalized and raw snapshots to distinguish radius drift from orientation or translation differences.

    Context

    Ribocode alignment behavior is implemented across two layers:

    • Application orchestration in src/App.tsx
    • Geometry/fitting methods in packages/molstar

    Recent benchmark work established one strong reference case and one weak case:

    • Strong case: 6XU6.cif -> 6XU8.cif, chain CU -> CU
    • Weak case: 7WTT.cif -> 7WTZ.cif, chain e -> e

    The fit already includes rigid-body rotation and translation. Experiments showed that adding post-fit translation-only behavior is not a reliable fix for weak correspondence cases.

    Decision

    1. Use benchmark-driven quality gates for alignment changes.
    2. Treat correspondence quality as the primary improvement target for weak cases.
    3. Keep implementation ownership split explicit:
      • App-level behavior/contracts documented in project docs.
      • Geometry-method behavior documented near molstar geometry implementation.

    Quality Gates

    Any alignment algorithm change must satisfy all of the following:

    1. No regression in strong-case benchmark behavior (6XU6/6XU8 CU -> CU).
    2. Material improvement target for weak-case benchmark behavior (7WTT/7WTZ e -> e), or a documented reason if deferred.
    3. Unit and E2E checks pass, including alignment metric tests.
    4. In-place and fallback paths are both validated when App.tsx realignment logic changes.

    Required Automated Checks

    Run at minimum:

    • npm test -- src/utils/alignmentGeometry.test.ts src/utils/realignment.test.ts src/App.test.tsx
    • npm test -- src/utils/alignmentPerformance.test.ts
    • npx playwright test e2e/sync-and-realign-camera.e2e.spec.ts
    • npx playwright test e2e/alignment-performance-cu-6xu6-6xu8.e2e.spec.ts
    • npx playwright test e2e/alignment-diagnostic-e-7wtt-7wtz.e2e.spec.ts

    Follow-up Work

    1. Investigate residue-correspondence-aware pairing in chain alignment for weak cases.
    2. Expand explicit automated coverage for residue-based chain correspondence behavior.
    3. Keep benchmark metrics in release notes when alignment internals change.

    Initial-load diagnostics (2026-11-23)

    Initial loading modifies coordinates during mmCIF parsing. An identity structure-transform matrix therefore does not establish that the initial fit is correct. Diagnose coordinate alignment separately from camera orientation before changing either.

    • Geometry diagnostics check an asymmetric structure with a known rotation and translation, including unequal selected-atom counts in both directions and atoms excluded from the fit. They exercise both the compiled runtime and the pinned Mol* TypeScript source.
    • The first diagnostic run passed all three compiled-runtime cases but failed both unequal-count cases in the pinned source. Local generated packages/molstar/lib geometry differs from the source: the runtime uses a shared rigid-transform helper that is absent from the source. Do not rebuild or treat a source-only defect as the cause of the observed viewer behavior without checking this provenance.
    • Initial-load browser diagnostics compare actual atomic coordinates for each dataset across viewers, record phosphorus counts and centroids, measure CU C-alpha distances using shared author residue IDs, and record camera forward/up dot products before manual realignment. The CU anchors are a diagnostic for this known pair, not an automatic correspondence policy.
    • The first browser run found identical coordinates across viewers for both datasets (219,765 reference atoms and 216,955 aligned atoms; maximum coordinate distance zero). Camera forward/up dot products were both 1 at capture time. Initial CU C-alpha RMSD was 107.963 Angstrom over 95 shared author-residue anchors; subsequent chain alignment reported 5.999 Angstrom and a 17.997-fold improvement. Initial phosphorus counts were 5,910 and 5,906. This reproduces a poor molecular fit despite coordinate and camera parity, but does not yet establish whether atom correspondence or another fitting detail is responsible.
    • Four of five browser checks passed. The full-CU residue-versus-chain check reached its 120-second total timeout while waiting for residue metrics; its final quality assertions were not reached. The other two residue checks passed. Do not consider residue realignment fully validated from this run. An isolated rerun also reached the 120-second timeout, so the failure cannot be attributed solely to concurrent unit-test/type-check work in the first run.

    Run diagnostics with:

    npm run test -- --run src/utils/alignmentGeometry.test.ts src/utils/alignmentPerformance.test.ts src/utils/realignment.test.ts
    npm run test:e2e:webgl -- e2e/initial-alignment-coordinate-diagnostic.e2e.spec.ts

    The source diagnostics intentionally remain failing pending a separate, validated fix. The browser diagnostic records initial fit quality without imposing an unverified RMSD threshold or camera-parity policy. Existing chain/residue quality gates remain required.

This is fixture-specific matching, not a general chain-homology or sequence-alignment algorithm. Duplicate identities are excluded.

Sequences include only residues with observed C-alpha coordinates, with alternate locations deduplicated. They are not complete deposited polymer sequences. Unknown one-letter codes do not count as identical anchors. This report does not change application pairing or establish a general acceptance threshold.

    7WTT/7WTZ e 20 / 55 20 20 (100% of aligned positions) e: 68 / Y: 11
    • CU is the strongest sequence candidate, but none of its 55 identical sequence-aligned residue pairs has matching author numbering. The earlier numbering-based proxy pairs different sequence positions.

    Reciprocal matching and RNA anchors (2026-11-23)

    Protein target matching is now checked in both directions. CU and e are unique top-scoring candidates reciprocally among observed protein chains.

    RNA candidates are extracted from observed C4' atoms, deduplicated by author chain/residue, then compared using Mol*'s default nucleotide scoring. All reference/ moving candidate combinations are scored. A match contributes sequence-identical anchors only if it is the unique best-scoring match in both directions; ties and non-reciprocal choices are excluded. The same score table supplies both rankings. Unknown residue codes never contribute identical anchors.

    • 6XU6/6XU8 has five reciprocal candidate pairs: A9, A7, A8, B2 and A5. The first four have identical observed sequences. A5 has 3,707 versus 3,703 observed residues, with 3,703 identical aligned positions. Together these yield 5,912 C4' anchors without using chain-name or author-number equality for pairing.
    • 7WTT/7WTZ has a reciprocal chain-2 pair with 1,575 versus 1,624 observed residues and 1,567 identical positions (99.5% reference and 96.5% moving coverage). Reference candidate q contains only one unknown C4'-bearing residue and is non-reciprocal; it contributes no fit anchors. C4' presence alone is not a validated RNA-polymer classification, so this is explicitly a candidate report.

    An offline fit using only those reciprocal, sequence-identical C4' anchors gives:

    Pair Fit C4' RMSD Evaluation P RMSD Evaluation protein CA RMSD Sequence-identical target CA RMSD
    6XU6/6XU8 2.479 2.520 2.139 3.052 (55 CU pairs)
    7WTT/7WTZ 11.062 10.841 9.908 3.597 (20 e pairs)

    P and protein CA evaluation atoms are excluded from this C4'-only fit. Broad evaluation still uses shared fixture identities; only target CA evaluation uses sequence-derived correspondence. The weak fixture's chain-e score remains worse than the initial 2.985-Angstrom score, so the existing gates do not permit claiming a universal improvement.

    Synthetic checks confirm RNA sequence pairing ignores renamed chains/renumbered residues, excludes unknown anchors, and reports equal scores for identical competing sequences. No runtime alignment, selector or chain/residue realignment was changed. Next investigate complete polymer metadata, tie/coverage acceptance and weak-fixture domain motion before proposing an automatic initial-load policy.

    Polymer metadata and weak-case residuals (2026-11-23)

    Offline candidate extraction now requires entity type polymer and the appropriate Mol* subtype (polyribonucleotide for RNA or polypeptide* for protein). Reference chain q in 7WTT is explicitly non-polymer, despite having a C4'-named atom and an inferred polypeptide subtype; requiring both type and subtype excludes it. The classified RNA candidates retain all 5,912 and 1,567 reciprocal anchors respectively, so previous candidate-fit measurements are unchanged. Hybrid RNA/DNA and DNA entities are not covered by this diagnostic policy.

    Weak-fixture per-chain residuals after the reciprocal RNA fit are not uniformly small. Independent offline fits on sequence-identical C-alpha pairs give:

    Chain Global-fit identity CA RMSD Independent sequence CA RMSD Sequence pairs Reference/moving identical coverage
    K 20.376 1.425 909 88.9% / 100%
    R 19.946 1.654 81 100% / 66.4%
    M 17.138 1.043 108 100% / 87.8%
    f 14.032 2.524 57 100% / 78.1%
    t 10.473 11.453 56 94.9% / 44.1%

    Global and independent columns use different correspondence policies and sometimes different pair counts; do not interpret them as a controlled before/after metric. Nevertheless, several large global residuals coexist with good local rigid fits, consistent with differing relative chain placement rather than a missing universal translation. Chain t remains a poor local fit and needs separate correspondence/ structural inspection. These findings do not prove domain motion or establish a single global transform that improves every chain.

    No production acceptance thresholds have been selected. Candidate uniqueness, reciprocity, known-residue identity, bilateral coverage and polymer classification must be considered together; a unique candidate can still have low coverage. The next implementation decision should distinguish initial whole-structure alignment from targeted chain alignment and explicitly define acceptable global/local trade-offs. Runtime chain/residue fitting remains unchanged.

    Approved developer-only integration (2026-11-23)

    Maintainer choices: expose only through a development URL opt-in; allow the documented weak-fixture global/local trade-off for this experiment only; if correspondence is uncertain, warn and leave centered coordinates unfitted (do not fall back to the legacy fit).

    The prototype in experimentalInitialAlignment.ts requires unique reciprocal RNA polymer matches, at least 20 known identical residues, 90% aligned identity and 80% identical coverage bilaterally for every observed RNA chain. Matching uses label-chain identity only to distinguish candidates, not to pair them across structures. A 50-million-cell comparison limit bounds the quadratic sequence aligner. Only RNA C4' anchors participate in this initial fit.

    Enable with ?experimentalInitialAlignment=1 on the development server before loading either file. Production and ordinary development loads remain unchanged. Session restoration explicitly bypasses the experiment; experimental session-baseline round trips are not supported yet. Both viewer parses receive the same explicit rotation/centroid transform, using the existing parser path. ReAligned loads and manual chain/residue fitting code are unchanged.

    Acceptance: strong-fixture evaluation P and protein CA RMSD below 3 Angstrom, sequence-identical CU CA RMSD below 4 Angstrom, coordinate parity across viewers, explicit rejected-match outcomes, and working manual chain realignment after the experimental fit. The weak-case exception does not relax default/release gates. Source/runtime provenance and the full-CU residue-test timeout still block promoting this experiment to a default.

    Verification of the integration: nine acceptance unit tests pass (including the 20-pair/80%-coverage boundary); the broader 33-test unit run before those two boundary additions passed. Browser checks passed for unchanged default coordinates, accepted experimental coordinates in both viewers, manual CU chain alignment after the experiment, and warned/centered protein-only rejection. A selected unchanged 7WTT/AlphaFold residue-realignment regression also passed. The Vite production build passed. Standalone type-checking reports only the two existing unassigned container diagnostics in MolstarContainer tests. The full suite was not run; the intentionally failing pinned-source geometry diagnostics and full-CU residue timeout remain open.

    Source/runtime geometry reconciliation (2026-11-23)

    The Mol* source on branch fix/rigid-alignment-centroid-mapping now uses the same rigid-coordinate helper as the previously working local runtime in all count branches. For extra moving atoms, the previous source added the moving centroid rather than the reference centroid. For extra reference atoms, it added the moving centroid before rotation and subtracted it afterward. Both paths now consistently apply R * (moving - movingCentroid) + referenceCentroid. Selection, truncation and rotation fitting policy are unchanged. The pinned source's single-pair translation safeguard, which was absent from the old generated runtime, is preserved.

    Both unequal-count diagnostics now pass against source and regenerated runtime. Additional single-pair source/runtime checks pass. Six Mol* Jest geometry tests pass, and the rebuilt application's focused 79-test unit/integration run passed before the two new single-pair checks. The subsequent geometry/performance/pair-tracking run passes all 15 tests.

    Build qualification: local dependencies were restored after TypeScript version drift and missing packages were observed; no dependency manifests or lockfiles were changed. The normal full library build remains blocked by unrelated Express server route-parameter type errors. A focused TypeScript build regenerated the geometry dependency tree in ESM and CommonJS, then ran the library asset/alias step. This does not qualify the full library build as passing. Parent type-checking still reports only the two existing MolstarContainer test diagnostics.

    Seven rebuilt browser checks passed: default and experimental initial coordinates, centered/unfitted rejection, CU and e chain benchmarks, repeat alignment in the camera regression spec, and the selected 7WTT/AlphaFold residue regression. CU remains at 5.999-Angstrom chain RMSD with 17.997-fold improvement. The weak e diagnostic remains poor (72.233-Angstrom RMSD over 262 chain-fit atoms); a passing diagnostic is not a quality approval. This chain-fit metric uses different atoms from the earlier offline 20-pair C-alpha comparison and must not be conflated with it.

    The reconciled source is committed and pushed to agdturner/molstar on branch fix/rigid-alignment-centroid-mapping, commit 2d4fd2c68fe4cdf600ebb38a84e9030bed4f8725. Ribocode's submodule pin is updated to this commit. Fetching the exact SHA from the configured ribocode-slola/molstar remote succeeded, so the submodule URL does not need to change for this checkpoint.
