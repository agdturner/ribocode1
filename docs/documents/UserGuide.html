    Data and Mol* Acknowledgements

    In publications, users should acknowledge the data sources used, and the underlying Mol* technology using a citation along the following lines:

    • David Sehnal, Sebastian Bittrich, Mandar Deshpande, Radka Svobodová, Karel Berka, Václav Bazgier, Sameer Velankar, Stephen K Burley, Jaroslav Koča, Alexander S Rose: Mol* Viewer: modern web app for 3D visualization and analysis of large biomolecular structures, Nucleic Acids Research, 2021; https://doi.org/10.1093/nar/gkab314.

    User Interface

    The Ribocode User Interface (UI) is best displayed on a screen at a width of 1200 pixels and a height of at least 800 pixels. UI interaction is normally via a mouse and keyboard.

    Important ownership model

    Ribocode has two data roles and two viewer columns:

    • AlignedTo is the reference dataset role.
    • Aligned is the dataset-to-align role.
    • Column A is where you load AlignedTo.
    • Column B is where you load Aligned.

    Both columns can show controls for both roles in MoleculeUI, but data ownership still follows the load points above.

    Theme workflow quick start

    Use this flow when working with chain/residue themes:

    1. Load AlignedTo in Column A.
    2. Optionally load Aligned in Column B.
    3. Open Representation Controls in either column.
    4. In Theme, choose Chain or Residue mode.
    5. Use Load to import a theme file, then pick it in the theme dropdown.
    6. Add a representation (or select an existing one) and set that row's Theme Type plus Chain Theme or Residue Theme.
    7. Use Save to export the currently selected theme.
    8. Use x to remove a theme that is not currently used by any representation.

    Theme library behavior:

    • Loaded custom themes are shared and can be applied to either dataset role (AlignedTo or Aligned).
    • The top Theme selector in Representation Controls sets what newly added representations will use by default for that mode.
    • Per-representation selectors are authoritative for that specific representation row.

    Tooltips

    Most controls in Ribocode provide hover tooltips.

    • Tooltips describe what a control does.
    • For toggle-style controls, tooltips describe the current state (for example, On/Off).
    • For disabled controls, tooltips explain what must happen before the control becomes enabled.

    This is especially useful in Representation Controls, Clipping Controls, and Select and Zoom Controls, where some actions depend on current dataset load state and current chain/residue selections.

    Residue Default behavior:

    • Choosing Default in a representation's residue selector maps to a role-specific default:
      • AlignedTo-default-residue-colors for AlignedTo representations.
      • Aligned-default-residue-colors for Aligned representations.

    Chain Selection

    When data are loaded, Ribocode enriches chain labels used in the Select tables for each dataset (AlignedTo or Aligned). Users can use the search box to quickly find chains by any part of the label, including:

    • label chain ID (e.g., ZB),
    • auth chain ID (e.g., auth CU),
    • UniProt accession,
    • RP family name,
    • molecule description (e.g., L22).

    Selecting a chain is done by selecting a row in the table.

    Ribocode combines metadata from the loaded mmCIF file and lookup tables to build a richer chain label.

    Depending on available metadata, labels can include:

    • RP family name (from RP_name_table_uniprot.csv lookup),
    • UniProt accession and/or gene name,
    • original chain identity with auth preserved (<label> [auth <auth>]),
    • molecule description from mmCIF entity metadata.

    Example enriched label:

    eL22 | P35268 | ZB [auth CU] | Ribosomal protein L22-like protein

    UniProt toggle behavior

    • Include UniProt accession in labels controls whether accession codes are shown in chain label text.
    • There is a control for each of AlignedTo and Aligned which can be configured independently.
    • Each chain section also displays UniProt cache progress (cached, pending, in-flight).
    • The per-dataset toggle state is saved and restored as part of session uiState.

    Supported File Formats

    This section defines what can be loaded in each file picker.

    1) Structure datasets (Load AlignedTo, Load Aligned)

    • Required format: CIF/mmCIF text structure files.
    • Expected extensions: .cif or .mmcif.
    • Ribocode validates both:
      • filename extension (.cif / .mmcif), and
      • file content looks CIF-like.
    • If either check fails, loading is rejected with a user-facing message.

    Examples:

    • 4UG0.cif
    • 6XU8.cif

    2) Colour/theme files (Load in Representation Controls)

    Supported theme file extensions:

    • .csv, .tsv, .txt, .json

    Supported table shapes:

    • Chain themes: two columns equivalent to chain,color
    chain,color
    LY,#3366FF
    e,#FF8800
    • Residue themes: two columns equivalent to residue_type,color
    residue_type,color
    ALA,#8CFF8C
    LYS,#4747B8
    G,#32CD32

    Header aliases accepted:

    • chain: chain, chain_id, pdb_chain, auth_asym_id, label_asym_id
    • residue type: residue_type, residue, residue_name, comp_id
    • color: color or colour

    Notes:

    • Legacy multi-column mapping files (for example mapping_with_colour_animal.txt) are not the target format for current colour loading.
    • For chain themes, values should be chain IDs.
    • For residue themes, values should be residue codes (for example ALA, LYS, G).

    3) Session files (Session > Load, Session > Load All)

    • Session files are JSON (.json).
    • Load restores session state and then asks you to manually select required datasets.
    • Load All restores state and embedded data from a single session file (when present).

    Sessions

    A user starting from scratch starts a session by loading a dataset in CIF file format via the Load AlignedTo button. As the data load, the coordinates for all the atoms are centralized so that the coordinate origin is at the centre.

    When the AlignedTo dataset is loaded several things happen:

    • The Sync control becomes actionable.
    • The Load AlignedTo button is replaced by the name of the dataset loaded.
    • The AlignedTo Select and Zoom Controls become actionable.
    • The Load Aligned button becomes actionable.
    • The MoleculeUI for AlignedTo in both columns populates and becomes actionable.
    • A default cartoon style 3D visual representation of the dataset appears in Viewer A.
    • In Viewer B, the loaded AlignedTo dataset is hidden by default.
      • Users can action the AlignedTo visibility (eye) button to toggle visibility.

    Next, the user can do several things:

    • Additional representations can be added via the + button in the Add Representation component. Initially this is set to add a spacefill representation, but other representation types can be selected.
    • Representation can be removed from the MoleculeUI components using the x buttons.
    • Custom colour themes can be loaded from file via the actionable Load Colours button and then selected in either column.
    • The 3D representation of the dataset in Viewer A can be rotated, zoomed and panned using mouse controls as normal with a Mol* viewer.
    • An Aligned dataset can be loaded via the Load Aligned button.
    • Subunits and chains can be selected and once selected more things can be done...
    • As an Aligned dataset is loaded, it's atom positions are centralized and aligned with the centralized AlignedTo atom positions using an algorithm.
    • In Viewer A, the loaded Aligned dataset is hidden by default. Use the Aligned visibility (eye) button in MoleculeUI to show it.
    • If a chain is selected, residue selection from that chain is supported and the Zoom, Highlight and Inspect controls become actionable for the chain.
    • Residue labels in Select follow Mol* style: code number [auth n] (for example GLY 70 [auth 70], A 12 [auth 12]).
    • If a residue is selected then residue Zoom, Highlight and Inspect controls become actionable.
    • If chains are selected for both AlignedTo and Aligned molecules, the Align Chains button can be actioned to apply chain-based re-alignment. If actioned, the Aligned viewer camera is set to match with the AlignedTo viewer camera (zoom, pan target, and orientation) so both viewers show the same viewpoint respectively.

    Re-align implementation note

    • Chain re-alignment now prefers an in-place transform of the currently loaded aligned structures for faster iteration.
    • Console diagnostics for re-alignment include fit-quality metrics (movingSelectedAtomCount, referenceSelectedAtomCount, atomPairCount, and rmsd). These can be examined when debug flags are enabled.

    Ribosome data can be downloaded from the RCSB Protein Data Bank in CIF format. Two datasets which align well are: 4ug0; and 6xu8.

    Synchronization is Off by default. If selected to be On, camera changes (rotation/pan/zoom) from the active viewer are propagated to the other viewer as relative deltas.

    Please refer to the Mol* viewer Documentation for details of the Mol* UI. In each Ribocode Molstar Container, the Mol* 3D Canvas is always visible and the additional Mol* panels (Sequence Panel, Main Menu, Control Panel, Log Panel) are hidden by default so as not to clutter the UI. Use the Show Advanced Mol* Controls button in a column to expand those hidden by default panels for advanced usage, and use Hide Advanced Mol* Controls to collapse them again. The Mol* viewer style is adapted so that the UI fits in a column of 600 pixels in width.

    Users can save and load a session via the Session menu. A Load rather than a Load all does not load the data. For security reasons data loading is a manual process, but once the AlignedTo and Aligned data are selected, the representations are recreated and the loaded session should be in the same state as when the session was saved.

    Session uiState persists Residue Zoom settings, per-dataset Include UniProt accession in labels settings, highlight toggle states, and selection display preferences (Highlight display, Dim unselected, and Strength), so visual behavior is restored consistently when a session is loaded.

    The Session > Save All saves all the data and all the UI state into a single file so that this can be shared and reloaded using Session > Load All.

    Troubleshooting Before Reporting Issues

    If you see unexpected behavior (for example unusual alignment/orientation, stale labels, or controls not reflecting recent actions), run:

    • Session > Reset Local Caches

    This performs a local troubleshooting reset for Ribocode in your browser and reloads the app. It clears local browser state used by Ribocode, including:

    • local storage/session storage
    • IndexedDB entries
    • service worker registrations
    • cache storage entries

    Recommended issue-reporting workflow:

    1. Reproduce the problem once.
    2. Run Session > Reset Local Caches.
    3. Repeat the same steps.
    4. If the issue still occurs, report it with the exact dataset filenames and steps.

    If the issue disappears after reset, include that detail in your report as it helps triage stale-state problems faster.
